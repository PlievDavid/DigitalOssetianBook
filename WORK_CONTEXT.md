# Контекст работы над «Адам»

Актуально на 6 октября 2026 года. Это сводка для продолжения разработки; инструкции по запуску находятся в [README.md](README.md).

## Принятые решения

«Адам» — адаптивный сайт для изучения иронского варианта осетинского языка на ASP.NET Core MVC и .NET 10. В решении два проекта: `IronLanguage.Web` (страницы, контроллеры, правила занятий) и `IronLanguage.Db` (PostgreSQL, EF Core, миграции, интерфейсы и реализации репозиториев). Для доступа к данным используется название «репозиторий» (`I…Repository`, `Ef…Repository`). Первая версия бесплатна и требует интернета; Flutter в неё не входит.

Сейчас развиваются аудиопазлы, перевод фраз, личный словарь, чтение книг, повторение слов, игра на подбор пар, очки, награды и серии дней. Диалоговый тренажёр подключён по задаче пользователя (ТЗ `docs/specs/dialogue-trainer.md`, ветка `feature/dialogue-trainer`); курсы, видеопазлы, подкасты, личный план и подписка отложены. Подключение полного осетинско-русского словаря пользователь пока отложил; машинный автоперевод также решено отложить целиком. Неизвестным словам нельзя показывать выдуманный перевод.

Демонстрационный режим уроков полностью удалён по решению пользователя: каталог, страницы прохождения, API слов урока, JavaScript и браузерная сессия. Главная содержит переходы к самостоятельным упражнениям; поиск по урокам убран из шапки. Курсы с последовательностью интерактивных задач могут быть добавлены позже.

Гостевой доступ: опубликованные книги, слова, аудиопазлы, перевод фраз и диалоги доступны без входа. Гость тренируется с опубликованными словами; личный словарь, прогресс и история требуют аккаунта. Гостевые попытки и диалоги используют снимки в ограниченном кэше памяти (30 минут бездействия, максимум два часа), привязаны к случайному HttpOnly-cookie и не пишут в БД. Общие правила проверки ответов используются и для гостя, и для аккаунта; гостевые диалоги сериализуют изменения через блокировку. При входе гостевой результат не переносится.

## Реализовано

- Аккаунты, вход, профиль и роль `Editor`. Публичная регистрация не выдаёт роль редактора. `/editor` защищён ролью; ссылка на редактор находится в профиле.
- На `/editor` сначала выбирают слово, аудиопазл, перевод фразы или книгу. Для каждого типа есть отдельная форма. Заполненный черновик можно сохранить, открыть повторно, изменить, посмотреть глазами ученика и опубликовать после подтверждения проверки текста, перевода и прав. Старые POST-маршруты создания и публикации сохранены для совместимости.
- Для аудиопазла запись обязательна, для слова необязательна, у перевода поля записи нет. Связанные слова выбираются поиском по опубликованному словарю без GUID. В тексте книги пробелы и пунктуация сохраняются; конкретное вхождение слова можно связать со словарной записью. Ручного ввода JSON в интерфейсе нет.
- Опубликованный материал редактируется через черновик новой версии. До публикации ученики видят прежнюю версию; публикация сохраняет ID и записывает историю без функции отката. Начатая попытка хранит снимок слов для сборки, ответа, записи и пояснения. При изменении книги сохраняются ID неизменённых глав и корректируется позиция чтения.
- Ученические страницы: `/audio-puzzles`, `/translate`, `/vocabulary`, `/word-practice`, `/game`, `/books`, `/progress`. `/game` — отдельная страница подбора пар; `/word-practice` содержит только повторение переводов. Для игры нужны хотя бы два сохранённых слова с разными переводами.
- В книге нажатие на слово показывает опубликованный перевод, пример и доступную запись, а также позволяет сохранить слово. Позиция чтения сохраняется в аккаунте. Неизвестные слова пока не переводятся автоматически.
- Ответы проверяются на сервере; повторная отправка не создаёт второй результат и очки. Попытки, словарь, чтение и прогресс привязаны к пользователю. JSON API расположен под `/api/v1`; адрес `/audio-puzzles` сохранён.
- Диалоговый тренажёр: тип `dialogue` в редакторе (персонажи, реплики и ходы вводятся тремя текстовыми блоками, проверка §6.2 ТЗ при сохранении), таблицы `Dialogues`, `DialogueSessions`, `DialogueRewards` (миграция `20261004074438_DialogueTrainer`), эндпоинты `/api/v1/dialogs*` со снимком условий в сессии, лестницей подсказок, пропуском хода и очками 10/день через `CompleteSession`. Страница `/dialogs` — лента чата, ответ выбором или текстом, сводка и история. Верный ответ ученика выделяется зелёным, неверный — красным: `wwwroot/js/dialog.js` помечает реплику ученика, а не последнюю строку ответа, поэтому следующая за ответом реплика собеседника остаётся нейтральной. Сравнение ответов — `DialogueScript.Normalize` по правилам §5 ТЗ: NFC, кавычки/тире/неразрывные пробелы к обычным, схлопывание пробелов, срез концевой пунктуации, нижний регистр без свёртки `ё`, `ӕ` и удаления `ъ`/`ь`.

## Последние изменения интерфейса

В ветке `codex/design-green-current` зелёная тема из `codex/design-green` совмещена с актуальным кодом и исправлением запуска из Visual Studio. Главная показывает аудиопазлы, перевод фраз и диалоги, книги и сохранение слов; старый каталог уроков и поиск не перенесены. Общая шапка и мобильная нижняя панель используют `theme-green.css`, `nav.js` и `_NavIcon`. Сохранены гостевые уведомления, признак авторизации для JavaScript и CSRF. Токены и адаптивность описаны в `DESIGN_SYSTEM.md`. Заголовки используют локальный Onest, основной текст — Golos Text; наличие Ӕ/ӕ проверено в файлах шрифтов и браузере. Градиенты героя перенесены на всю площадь баннера, чтобы убрать горизонтальный шов под текстовым блоком.

Подбор пар остаётся на `/game`, повторение слов — на `/word-practice`. В редакторе материалы разделены на черновики и опубликованные с фильтром по типу.
Гостевые занятия после перезагрузки страницы начинаются заново; восстановление диалогов и плиток доступно аккаунтам. Это ограничение явно отражено в README и AC-02. Cookie гостя продлевается при запросах состояния, а снимок по-прежнему живёт максимум два часа. Заполнение кэша обрабатывается компакцией и проверкой сохранения; при отказе новый старт возвращает 503. Гостевой Revision увеличивается только при сохранении ответа, завершение проверяет ожидаемую версию без дополнительного увеличения, как в БД-пути. История диалогов гостям не рендерится сервером.

Миграция `DialogueTrainer` применена на локальной базе `adam`, и сценарий диалога проверен по HTTP: регистрация и роль редактора, создание и публикация диалога, предпросмотр и список `/editor`, старт сессии, неверный ответ, отказ латиницы без попытки, подсказка по порогу, верный ответ со знаком препинания, выбор кнопки с подсветкой верной, завершение с начислением 10 очков, повторные прохождения без новых очков, отказ пропуска непропускаемого хода, восстановление сессии, история, запрет `/editor` пользователю без роли. Не выполнено: проверка в браузере (поведение `dialog.js`, узкий экран, клавиатура) и `node --check` — Node.js в этой среде не установлен. В браузере не подтверждено и исправление подсветки ответа. Временные скрипты проверки лежат в `%TEMP%\opencode`; созданные ими тестовые материалы и учётные записи из локальной базы удалены.

В локальной базе `adam` опубликован учебный диалог «Дæ бон хорз, Алан!» (уровень 1, диалект Iron, персонаж «Собеседник», четыре реплики, один ход ввода на реплике 2 с эталоном «Дæ бон хорз»). Запись внесена прямо в `Dialogues` и `ContentRevisions` тем же JSON, который выдаёт сериализация разобранного материала, минуя форму редактора, поскольку у пользователя нет роли `Editor`. Чтобы материал совпал с этим правилом, в `DialogueScript` латиницей считаются только `A–Z` и `a–z`, а `Æ`/`æ` приводятся к осетинской `ӕ`: `æ` — не латинская буква, а другая запись той же буквы. ТЗ (§5.2, §5.3) дополнено этими правилами.

Рядом опубликован второй учебный диалог «Дæ бон хорз, Алан! — выбор»: тот же материал и персонаж, но ход на реплике 2 — выбор из трёх вариантов («Дæ бон хорз», «Дæ изæр хорз», «Фæндараст»), порог подсказки 1, пропуск запрещён. Запись внесена тем же способом, что и первый диалог, JSON получен сериализацией разобранного материала и сверен с базой.

В диалогах слова теперь кликабельны и у собеседника, и у ученика: сервер считает совпадения при запросе (`DictionaryService.Matches` вынесен из `Prepare` и используется книгами и диалогами), `DialogsApiController` добавляет в `Start`, `Session` и `Answer` поле `dictionary` со значениями senses, а `dialog.js` показывает перевод, примечание и кнопку «В мой словарь» (`POST /api/v1/vocabulary/dictionary/{id}`), попап закрывается `Escape`. Привязки не сохраняются в `ScriptJson`, поэтому обновление словаря не требует переиздания диалогов. Проверено по HTTP на временной учётной записи: «хорз» — 3 значения, «бон», «куыд», «дæ» — по одному-два, «Алан» и «мын» — без совпадений; ответ с `æ` принимается и возвращает `correct=true`, добавленные реплики содержат `matches`, а чтение сессии возвращает 10 значений словаря. В браузере попап не проверялся.

Оба диалога вынесены в сиды: `IronLanguage.Web/Data/dialogues/dialogues.json` в формате формы редактора (`title`, `dialect`, `level`, `characters`, `lines`, `turns`). Служба `DialogueSeedService` и команды `dialogue-check` (только чтение) и `dialogue-import` (создание или обновление по точному названию) позволяют загрузить их в новую базу. Обновление идёт через обычную схему версий: новая ревизия и публикация, поэтому история не теряется, а повторный запуск не создаёт дублей. Редактор нужен только когда импорт действительно пишет; его почта передаётся аргументом, а при полном совпадении с базой команда завершается успешно и редактора не спрашивает. Проверено на изолированной схеме `probe` в локальной базе: создание, идемпотентный повтор, обновление до версии 2 с двумя опубликованными ревизиями, отклонение невалидного сида и понятная ошибка без роли редактора; схема затем удалена, данные `adam` не изменены.

По замечаниям ревью к пул-реквесту #18 устранены три дефекта. `EditorFormModel.FromPayload` и предпросмотр редактора сравнивают `CharacterId` с `DialogueScript.StudentId`, а не с отображаемым именем, поэтому реплика ученика больше не превращается в «?» и не ломает повторное сохранение. Сессия диалога получила колонку `DialogueSession.Revision` (миграция `DialogueSessionRevision`, значение по умолчанию 1): `SaveSessionState` и `CompleteSession` обновляют строку только при совпадении ожидаемой версии; версия увеличивается при сохранении состояния, а `DialogueService.Answer` при расхождении выбрасывает `DialogueConflictException`, которая возвращается как HTTP 409 с сообщением о другой вкладке. Версия читается в локальную переменную до любых записей, иначе EF отдаёт уже увеличенное значение. В `api.js` у ошибки появился `status`, в `dialog.js` — счётчик поколений запросов, `AbortController` при старте нового диалога и выходе из него, проверка принадлежности ответа текущей сессии и перезагрузка состояния по `GET /dialogs/sessions/{id}` при 409. Проверено на изолированной схеме `probe` миграциями и реальными запросами: три параллельных ответа дают ровно одну запись и две ошибки конфликта без потери обновлений, завершение начисляется один раз, повторный ответ после завершения возвращает `finished` без исключения, вторая вкладка увеличивает `Revision` ровно на единицу и не затирает состояние первой. Локальные тесты: 77, включая новые проверки на разбор редактора и гонку; браузер и `node --check` по-прежнему недоступны, визуальную проверку двух вкладок нужно выполнить вручную. Тот же паттерн версий применить к `SaveDraft`/`CompleteAttempt` упражнений — отдельная задача.

Повторное ревью подтвердило исправление трёх дефектов и нашло один в восстановлении после 409. Ветка конфликта вызывала `resync` и выходила до снятия блокировки, а `resync` глотал ошибку запроса состояния, поэтому при отказе GET поле ответа и все кнопки оставались `disabled` навсегда и повторить запрос было нечем. Теперь `resync` возвращает признак успеха, проверяет поколение запроса и совпадение активной сессии, а при отказе показывает блок `#dialog-sync-actions` с кнопками «Обновить диалог» (повторяет запрос состояния) и «К списку». Композер остаётся заблокированным: состояние неизвестно, отправлять ответ вслепую нельзя. При успешной синхронизации блокировка снимается явно, а не побочным эффектом `renderTurn`; `back()` и неудачный `start()` сбрасывают `busy`, поэтому заблокированное поле не переживает переход между диалогами. Блок действий вынесен из `<p role="status">`, чтобы не ломать live-регион для скринридеров. Дефект воспроизводился в headless Edge; локально `node --check` и сценарий «409, затем отказ GET» выполнить нельзя — Node.js и браузер недоступны.

Проверенного стартового контента пока нет. Для запуска нужны 30 озвученных фраз, 50 слов и 3 коротких адаптированных текста с подтверждёнными правами. Их не следует заменять случайными или автоматически сгенерированными переводами. Тестовый скрипт с учётными данными не сохранялся.

## Где продолжать

Подготовлено UX-предложение в `UX_CONTENT.md`: три учебных раздела («Упражнения», «Мои слова», «Книги»), результаты и редактор в профиле, подбор пар внутри личного словаря, тексты страниц и состояний. Это предложение, а не реализованная навигация. Демонстрационный каталог уроков удалён; упоминания пробного урока в старых макетах относятся к прежним концептам. При дальнейших изменениях сверять фактический контент и не переносить демонстрационные названия из PNG-макетов.

- `IronLanguage.Db/Entities.cs`, `AdamDbContext.cs`, `Repositories.cs`, `EditorRepository.cs` — данные и репозитории; миграции — в `IronLanguage.Db/Migrations`.
- `IronLanguage.Web/Controllers/EditorController.cs` и `EditorWorkflowController.cs` — совместимые старые POST-маршруты и новый workflow редактора.
- `IronLanguage.Web/Controllers/LearningApiController.cs` и `Services/LearningService.cs` — ученический API и проверка занятий.
- `IronLanguage.Web/Views/Shared/_Layout.cshtml`, `wwwroot/css/features.css`, `wwwroot/js/nav.js` — шапка и меню.
- `IronLanguage.Web/Views/Practice/WordPractice.cshtml`, `Game.cshtml`, `wwwroot/js/word-practice.js`, `game.js` — повторение и отдельная игра.
- `IronLanguage.Web/Services/DialogueService.cs` — разбор и валидация скрипта (`DialogueScript`) и сценарий сессии; `Services/DialogueDictionary.cs` — сопоставление слов реплик со словарём; `Services/DictionaryService.cs` — общий поиск форм и значений для книг и диалогов; `Controllers/DialogsApiController.cs`, `Views/Practice/Dialogs.cshtml`, `wwwroot/js/dialog.js` — API и страница ученика.
- `IronLanguage.Tests` — локальный проект с тестами правил сравнения, редактора диалогов и сессии; в репозиторий не входит, запускается отдельно.
- `README.md` — настройка PostgreSQL, миграций и роли редактора. Секреты в репозитории не хранить.

Во время разработки локальный сайт запускался на `http://127.0.0.1:58322` с PostgreSQL на порту `58321`. Это временное окружение, а не публикация; процессы могут остановиться после закрытия сессии. На момент записи файлы проекта отображались в Git как untracked — не удалять их при очистке.
