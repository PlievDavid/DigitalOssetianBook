# Развитие курсовой системы

Основание: согласованное 10 ноября 2026 года ТЗ в задаче разработки. Это список выполнения, а не заявление о готовности функций.

## Принятые правила

- Материалы по умолчанию личные и предназначены только для курсов. Публичное размещение и разрешение другим преподавателям — независимые настройки.
- Отзыв разрешения сохраняет ранее опубликованные включения, но запрещает новые включения и обновления. Административная блокировка закрывает и сохранённые снимки.
- Неизвестный владелец материала требует административного разбора. Владельца нельзя выводить из последнего редактора.
- Библиотека уроков поддерживает связанные версии и независимые копии. Обновление связанного урока применяется в выбранные черновики, без автоматической публикации курсов.
- Ученик автоматически получает актуальную публикацию; условия начатого ответа сохраняются. Прогресс — по блокам, успешное упражнение считается одним блоком независимо от числа внутренних шагов.
- Автор видит имена и результаты учеников только собственных курсов. До начала обучения показывается уведомление. Email, свободные ответы и экспорт персональных данных в первый релиз не входят.
- Используются существующие Editor/Admin, без модерации, новых ролей, платежей и генерации учебных материалов.

## Текущий технический срез

Повторная попытка: POST `/api/v1/course-sessions/{id}/retry` принимает `blockId` и `attemptId`. Создаётся новая попытка по исходному снимку; старая запись не изменяется. Повтор того же запроса не заменяет уже созданную попытку. Запрос ответа поддерживает `attemptId` для отклонения устаревшей вкладки. Проверка завершения требует `Correct == true` для пользователя и гостя. Схема БД в этом срезе не меняется.

Остальные пункты выше остаются незавершёнными. Текущая библиотека материалов пока не обеспечивает принятую модель личного доступа.
