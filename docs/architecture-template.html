3. IronLanguage.Web

3.1. Назначение и границы

Web-проект принимает HTTP-запросы, формирует Razor-страницы и JSON-ответы, проверяет учебные ответы, обрабатывает редакторские формы и хранит загруженные файлы. Гость работает с опубликованными материалами без записи личного прогресса. Аккаунт включает персональные данные. Курсы, видеопазлы, подкасты, личный план, подписка, офлайн-режим и оценка произношения не реализованы в текущем объёме. Диалоги уже подключены в коде.

3.3. Архитектурный стиль

Монолитное ASP.NET Core MVC-приложение с разделением на два проекта: Web и библиотеку данных. Одна единица запуска; IronLanguage.Db не является отдельным сервером или HTTP-сервисом. PostgreSQL работает отдельно. Слои организованы папками, а не самостоятельными Domain/Application-сборками. Такой вариант соответствует текущему объёму и позволяет выполнять начисление очков и публикацию в транзакциях одной БД.

API v1 уже задан в URL. Общее соглашение для следующей версии, cursor/page-пагинация и единый формат ошибок не реализованы. Каталоги и история возвращаются списками целиком. Ошибки: 400 для неверного ответа / CSRF, 401 для API без входа, 404 для недоступного объекта, 409 для конфликта диалогового состояния / завершённого черновика попытки, 503 при невозможности сохранить новый гостевой снимок. Часть ошибок возвращает {error}, часть — пустой ответ; автоматическая валидация ApiController может вернуть стандартный validation problem.

Повторный ответ на завершённую попытку возвращает alreadySubmitted=true. CompleteAttempt и дневные ключи наград защищают повторное начисление. Отдельного Idempotency-Key нет. Гостевой Start создаёт новое занятие; повторный старт не обязан возвращать прежний ID.

3.7. Аутентификация и права

CookieAuthentication: Adam.Auth, HttpOnly, SameSite=Lax, срок билета 30 дней и SlidingExpiration. Вход формирует NameIdentifier, Name и роль Editor только при Users.IsEditor=true. PasswordHasher<UserAccount> хранит хэш; публичная регистрация роль не выдаёт. После изменения IsEditor нужен повторный вход для обновления claims. LoginPath=/account/login; API без входа получает 401. JWT/OAuth, MFA, сброс пароля и динамический отзыв роли в исследованном коде не настроены. Cookie.SecurePolicy для Adam.Auth явно не задан; обязательный Secure следует проверить при production-настройке.

3.8. Асинхронная обработка

Используются async/await, EF Async и CancellationToken в запросах. Очередей, брокеров, BackgroundService и планировщика в Program.cs нет. Импорт словаря и сидов диалогов — явные CLI-команды, а не фоновые задания. Событийной шины и outbox нет. SemaphoreSlim в гостевом снимке упорядочивает ответы в одном процессе.

3.9. Кэширование и гостевые снимки

GuestLearningStore создаёт отдельный MemoryCache с SizeLimit=1024: одна запись имеет Size=1, это лимит числа снимков, а не мегабайт. SlidingExpiration=30 минут, абсолютный срок=2 часа. При заполнении Compact(0.1) освобождает часть записей; неудачная запись приводит к GuestCapacityException и HTTP 503. Ключ: (тип состояния, owner, id). Adam.Guest — случайный GUID, HttpOnly, SameSite=Strict, MaxAge=2 часа, Secure при HTTPS; cookie обновляется при обращении к Owner().

При перезапуске снимки теряются. После перезагрузки страницы гостевой интерфейс начинает новое занятие; перенос результата в аккаунт не реализован. Кэш не разделяется между Web-репликами. Redis/CDN и отдельный кэш каталога не настроены. Для словарных подсказок в диалогах DictionaryService.Matches читает активные формы; это вычисление по запросу, а не постоянный глобальный кэш.

3.10. Ошибки и логирование

Program.cs очищает logging providers и подключает AddConsole. appsettings задаёт Default=Information, Microsoft.AspNetCore=Warning. JSON-формат логов, сквозной traceId в каждом API-ответе и OpenTelemetry не настроены. Home/Error показывает Activity.Current.Id или HttpContext.TraceIdentifier; вне Development включены UseExceptionHandler и HSTS. JS api.js сохраняет HTTP status в ошибке и читает поле error, иначе показывает общую русскую ошибку.

У диалогов 409 приводит к синхронизации состояния; при отказе GET показаны действия «Обновить диалог» / «К списку». Circuit breaker, явно настроенные retry БД и HTTP-политики не найдены. Их нельзя считать существующими гарантиями отказоустойчивости.

3.11. Конфигурация и секреты

Подключение: ConnectionStrings__Adam; ключи cookie: DataProtection__KeysDirectory, по умолчанию .data-protection-keys под ContentRoot. В рабочем окружении перед запуском / проверками БД загружается игнорируемый .run-local/connection.ps1. Содержимое и секреты не включаются в документ. appsettings содержит только конфигурацию без пароля; environment перекрывает файл. Секрет-менеджер не подключён.

Data Protection сохраняет ключи на диск с ApplicationName="Adam". Постоянный защищённый том обязателен для сохранения входа между перезапусками. Политика защиты ключей at-rest зависит от окружения и требует отдельной настройки.

3.12. Запуск и развёртывание

Сайт запускается через dotnet run --project IronLanguage.Web/IronLanguage.Web.csproj. Миграции применяются до обслуживания запросов. Автоматического MigrateAsync на обычном старте нет; dictionary-import и dialogue-import применяют миграции в своих CLI-ветках. В коде dialogue-check является dry-run и миграции не применяет, несмотря на более широкую формулировку в README.

Dockerfile, production pipeline и отдельные stage/prod-топологии в репозитории не найдены. ASPNETCORE_ENVIRONMENT управляет стандартным режимом ASP.NET Core. Для публикации нужны PostgreSQL, сохранение wwwroot/media и ключей, HTTPS и корректная настройка reverse proxy. CI/CD: предлагаемая последовательность build → JS checks → тесты → отдельное применение миграций → публикация → smoke; это рекомендация, не реализованный workflow.

3.13. Тестирование

В решении нет отслеживаемого тестового проекта. WORK_CONTEXT описывает локальный игнорируемый IronLanguage.Tests (xUnit), прежние прогоны правил, редактора, конкурентной записи и HTTP-проверок. Число прошлых тестов не является текущим измерением покрытия. Указаны предыдущие браузерные проверки 1280/360 и ограничения подготовленной БД.

Обязательная проверка C#/Razor: dotnet build IronLanguage.slnx --no-restore -v:quiet. Для JS — node --check. Для учебных изменений проверяются владелец, CSRF, повторный ответ, UTC-награды, старый снимок после публикации и переход черновик → публикация. В этой задаче изменяется только HTML-документация; приложение и БД не изменяются.

4. IronLanguage.Db и PostgreSQL

4.1. Назначение

IronLanguage.Db — библиотека net10.0 с сущностями, AdamDbContext, интерфейсами и реализациями репозиториев и миграциями. Данные хранит PostgreSQL; браузер напрямую к нему не обращается. Сохраняются учебные материалы, словарные значения, версии, аккаунты и персональный прогресс. Гостевые попытки / сессии в эти таблицы не вставляются.

4.2. СУБД и обоснование

В Program.cs и фабрике DbContext используется UseNpgsql. Причины, следующие из кода: транзакции, ON CONFLICT, составные PK, частичные уникальные индексы версий, поддержка EF Core. Документального выбора между несколькими СУБД не найдено; таблица ниже — оценка переносимости, а не история решений.

4.4. Физическая модель

Колонки, типы, nullable, PK и индексы получены из AdamDbContextModelSnapshot; SQL DEFAULT дополнительно сверены с цепочкой миграций. JSON-поля здесь имеют PostgreSQL-тип text, а не jsonb. «—» означает отсутствие SQL DEFAULT; значения C# — инициализаторы / значения типа, не default базы. Схема описывает результат миграций репозитория; состояние живой БД в этой задаче не проверялось. Отдельно EF обслуживает служебную таблицу __EFMigrationsHistory (MigrationId, ProductVersion); она не является учебной сущностью.

4.5. Нормализация

Учебные материалы, главы, словарные формы, личные слова и дневные награды разделены на таблицы. Формально заявленной нормальной формы в проекте нет. Снимки Attempts, DialogueSessions и ContentRevisions сознательно дублируют условия: редактирование материала не должно менять начатую попытку. JSON в text хранит структуру плиток, реплик и состояния; это компромисс между удобством версий и контролем связей в БД.

4.6. Индексы и производительность

Индексы перечислены для каждой таблицы. Users.Email ускоряет вход и запрещает дубли; DictionaryForms.SearchKey — поиск; Chapters(BookId,Number) — уникальный порядок глав; Attempts и DialogueSessions(UserId,MaterialId,CompletedAt) — активные занятия. ContentRevisions ограничивает один черновик и уникальную опубликованную версию.

Подтверждённых EXPLAIN-замеров и нагрузочного профиля нет. Зоны измерения: чтение всех DictionaryForms в Matches, последовательные запросы слов в LearningService.Card, каталоги без пагинации, чтение истории и расчёт серий дней. Предложение: EXPLAIN (ANALYZE, BUFFERS) на подготовленной тестовой БД с реальными объёмами; индекс добавлять после замера и оформлять миграцией.

4.7. Транзакции и целостность

CompleteAttempt выполняет условный UPDATE WHERE CompletedAt IS NULL и UserId совпадает, вставку ExerciseRewards ON CONFLICT DO NOTHING, дневные очки и достижения в одной транзакции. CompleteSession дополнительно сравнивает Revision. За первое завершение конкретного упражнения / диалога в день UTC начисляются 10 очков; награда за упражнение привязана к завершению, а не только к правильности ответа. Повтор в тот же день не начисляет новые очки.

DialogueSessions.SaveSessionState обновляет только ожидаемую Revision и увеличивает её; конфликт приводит к 409. Attempts.SaveDraft не имеет Revision: конкуренция нескольких вкладок для черновика остаётся отдельной зоной роста. Гостевые ответы упорядочиваются SemaphoreSlim и не выполняют транзакций прогресса БД.

Публикация и импорт используют транзакции. Уровень изоляции в коде явно не задан; используется уровень подключения по умолчанию PostgreSQL, обычно READ COMMITTED. Явных распределённых блокировок и Serializable нет. ACID относится к PostgreSQL-транзакциям, не к совместной атомарности БД и локальных медиафайлов.

4.8. Миграции

Инструмент EF Core; миграции в IronLanguage.Db/Migrations, snapshot согласует модель. История включает InitialCreate, ExerciseRewards, ExerciseWords, AttemptDraft, EditorVersions, DictionaryLookup, AzarBook, BookMetadata, ArchiveMaterials, DialogueTrainer, DialogueSessionRevision. Некоторые миграции содержат данные, не только DDL. Время имени миграции не равно дате публичного выпуска.

Имеются методы Down, но формальная production-стратегия rollback / forward-only не установлена. Применение миграций и импорт меняют БД; их нельзя использовать как обычную проверку сборки. migration-check генерирует SQL и сообщает о расхождении модели; dictionary-check проверяет CSV. dialogue-check сравнивает сиды с БД без записи; dialogue-import требует Editor только если меняет материалы.

4.9. Резервное копирование и восстановление

Настроенная частота backup, WAL-архивирование, автоматическое восстановление и проверенные RPO/RTO в коде не подтверждены. README требует сохранять PostgreSQL, wwwroot/media и ключи Data Protection. Предлагаемые цели пилота из спецификации: RPO ≤ 24 ч, RTO ≤ 4 ч; требуют согласования.

План перед публичным запуском: согласовать удержание копий, выполнять согласованную копию БД и медиа, ограничить доступ к ключам, провести восстановление в отдельное окружение и проверить вход, опубликованную книгу, медиа и прогресс. Это список необходимых работ, а не уже работающий backup-сервис.

4.10. Безопасность БД

Роли PostgreSQL, TLS подключения, шифрование дисков / backup, аудит и маскирование PII не заданы как готовая инфраструктура в репозитории. ConnectionStrings__Adam определяется окружением; его секретные значения не раскрываются. Users хранит Email и PasswordHash; прогресс относится к конкретному UserId. Серверные проверки владельца реализованы, но не заменяют ограничений доступа к самой БД.

Рекомендации перед production: отдельные минимальные роли приложения и миграций, закрытая сеть, проверяемый TLS, защищённые копии и ключи, отсутствие PII в логах и политика хранения. Они не объявляются действующими настройками.

4.11. Масштабирование

Репликация PostgreSQL, шардирование, партиционирование и Redis не настроены. Текущая схема рассчитана на один Web-процесс с локальным GuestLearningStore и файловыми медиа. Для нескольких реплик понадобятся общие медиа и ключи Data Protection; гостевые снимки потребуют sticky routing или отдельного распределённого решения. Ни одно из этих изменений не внесено этой документацией.

4.12. Мониторинг

В проекте нет настроенных экспортёров метрик БД, slow-query политики или алертов. Console logging — существующее средство диагностики. Предлагаемые метрики: соединения и ожидание пула, долгие запросы, размер таблиц, блокировки, ошибки транзакций, свободное место БД / медиа, возраст резервной копии и доля HTTP 503 гостевого старта. Пороги должны следовать из измерений, а не из выдуманного SLA.

5. Сквозные аспекты

Безопасность — реализовано

CSRF на изменяющих API и редакторских формах, включая гостевые ответы. Cookie auth и роль Editor. Сервер собирает ответ из проверенных индексов и начисляет очки. SQL параметризуется; Razor кодирует вывод. Редактор подтверждает текст, перевод и права. Загрузка ограничена форматом / размером; нельзя считать проверку расширения полноценной проверкой каждого аудиофайла.

Безопасность — требуется оценка

Rate limiting, MFA, CSP, общая защита от перебора, аудит и production-политика секретов не настроены как готовый набор. CORS middleware не подключён; фронтенд работает same-origin. Обзор по OWASP должен проводиться отдельно; документ не утверждает его прохождение.

Язык и учебные правила

UTF-8, Ӕ/ӕ; чтение сохраняет исходные пробелы и пунктуацию. Словарные ключи нормализуют æ/ӕ и ударение; диалоговый ввод имеет собственную нормализацию. Эти правила нельзя автоматически переносить на все типы заданий. Неизвестные переводы не генерируются.

Версии и отказоустойчивость

Начатые попытки используют снимок старой версии; публикация не меняет их условия. Гости теряют состояние при рестарте и вытеснении кэша. Аккаунты читают сохранённое из PostgreSQL. При недоступной БД готового failover / офлайн-режима нет. Наблюдаемость ограничена текущими логами, SLO не измерен.

6. Развёртывание

Подтверждено кодом / локальным запуском:

Браузер ── HTTP/HTTPS ──▶ ASP.NET Core / IronLanguage.Web
                               ├─ EF / IronLanguage.Db ──▶ PostgreSQL
                               ├─ wwwroot/media (аудио / обложки)
                               ├─ .data-protection-keys (cookie keys)
                               └─ GuestLearningStore (память процесса)

Предлагаемая production-топология — ещё не настроена:

Браузер ── HTTPS ──▶ Reverse proxy ──▶ Web ──▶ PostgreSQL
                                      │          │
                                      ├─ media   └─▶ backup-хранилище
                                      └─ ключи ─────▶ защищённая копия

Балансировщик с несколькими Web-репликами требует отдельного решения
для гостевых снимков, общих медиа и ключей.

Локальные порты из WORK_CONTEXT — временное окружение, не адрес production. В этой задаче приложение, миграции и импорты не запускались. Для эксплуатации сначала согласуются TLS, домен, хранилища, мониторинг и процедура восстановления; репозиторий сам по себе не доказывает наличие работающего сервера.
