# Инструкции для работы над «Адам»

## Проект и источники контекста

«Адам» — адаптивный сайт для изучения иронского варианта осетинского языка на ASP.NET Core MVC и .NET 10, с PostgreSQL и EF Core.

Перед изменениями прочитайте `README.md` и `WORK_CONTEXT.md`. Для упражнений и чтения книг используйте `EXERCISES_SPECIFICATION.md`; для интерфейса сверяйтесь с `DESIGN.md`. `TECHNICAL_SPECIFICATION.md` содержит общий контекст: не считайте все описанные там возможности уже реализованными. При расхождениях проверяйте текущий код и явные требования пользователя.

## Структура и архитектура

- `IronLanguage.slnx` — решение.
- `IronLanguage.Web` — контроллеры, Razor-представления, учебные сервисы и статические ресурсы.
- `IronLanguage.Db` — сущности, контекст EF Core, миграции, интерфейсы и реализации репозиториев.
- `IronLanguage.Db/Migrations` — миграции и снимок модели.
- `IronLanguage.Web/Data` — данные для импорта.

Следуйте существующим соглашениям кода. Доступ к данным оформляйте через репозитории (`I…Repository`, `Ef…Repository`), учебные правила сохраняйте в сервисах. Не добавляйте новые платформы или крупные зависимости без необходимости для текущей задачи.

## Правила продукта и данных

- Интерфейс и пояснения пользователю пишите по-русски. Сохраняйте осетинские символы, включая `Ӕ` и `ӕ`, кодировку UTF-8, пробелы и пунктуацию в книгах.
- Используйте только подтверждённые переводы и материалы с установленными правами. Не выдумывайте переводы неизвестных слов и не подменяйте учебный контент автоматически сгенерированным.
- Полный словарь и машинный автоперевод отложены; не включайте их в сторонние задачи. Курсы, видеопазлы, диалоги, подкасты, личный план и подписка также вне текущего объёма, если пользователь не попросил иначе.
- Ученикам доступны опубликованные материалы. Изменение опубликованного материала проходит через черновик новой версии; начатые попытки используют сохранённый снимок условий.
- Ответы и очки проверяются сервером. Повторная отправка ответа не должна повторно начислять очки. Сохраняйте существующие ограничения начисления и расчёт дней активности по UTC.
- Попытки, личный словарь, прогресс и позиция чтения принадлежат конкретному пользователю. Проверяйте доступ к чужим данным.
- Редактор защищён ролью `Editor`; публичная регистрация её не выдаёт. Записывающие запросы требуют действующей авторизации и защиты от CSRF согласно существующему механизму.
- Сохраняйте совместимые маршруты и ID неизменённых глав; при изменении книги учитывайте сохранённую позицию чтения.

## Безопасность рабочего окружения

Не записывайте пароли, строки подключения с секретами, токены и тестовые учётные данные в репозиторий или отчёты. Строка подключения задаётся через `ConnectionStrings__Adam`; порядок настройки описан в `README.md`.

Не удаляйте пользовательские изменения и untracked-файлы при очистке. Не очищайте PostgreSQL, загруженные медиа и ключи Data Protection ради сборки. Каталоги `bin`, `obj`, `.tools`, `NuGet`, `artifacts`, `.run-*`, `.data-protection-keys` и `wwwroot/media` могут содержать локальные или генерируемые данные; не включайте их содержимое в изменения без явной необходимости.

Изменения схемы оформляйте миграциями EF Core и согласованным снимком модели. Применение миграций и `dictionary-import` меняют данные: используйте подготовленную локальную базу и учитывайте задачу пользователя. Не запускайте импорт как обычную проверку сборки.

## Проверка изменений

Для изменений C# и Razor выполните из корня проекта:

```powershell
dotnet build IronLanguage.slnx --no-restore -v:quiet
```

Если зависимости ещё не восстановлены:

```powershell
dotnet restore IronLanguage.Web/IronLanguage.Web.csproj --configfile NuGet.Config
```

Для изменённых JavaScript-файлов выполните `node --check <путь-к-файлу>`, если Node.js доступен. Запускайте существующие подходящие тесты, если они есть. При изменениях интерфейса проверяйте широкое и узкое окно, работу клавиатурой и отображение осетинских букв. Для изменений учебных правил и редактора проверяйте затронутый сценарий, права доступа, повторную отправку и переход между черновиком и публикацией.

Не считайте ручную проверку выполненной без фактического запуска. В итоговом сообщении кратко укажите изменения, выполненные проверки и ограничения окружения. Предупреждение `NU1900` о недоступном индексе уязвимостей отделяйте от ошибок сборки.

## Документация

Обновляйте `README.md`, если меняются запуск, настройка или доступные функции. При существенных решениях для продолжения работы актуализируйте `WORK_CONTEXT.md`, не превращая его в журнал каждого мелкого изменения. Вносите только изменения, связанные с текущей задачей.

## Коммиты и отправка на GitHub

После каждой завершённой задачи выполняйте необходимые проверки и создавайте коммит с понятным описанием. Перед отправкой на GitHub (`git push`) спрашивайте разрешение пользователя и выполняйте отправку только после его явного согласия. Включайте в коммит только изменения текущей задачи; не добавляйте посторонние пользовательские изменения, секреты и локальные данные. Не используйте принудительную отправку (`force push`). Если коммит или отправка не удались, сообщите причину и состояние локальных изменений. В итоговом сообщении указывайте, создан ли коммит и отправлен ли он на GitHub.
